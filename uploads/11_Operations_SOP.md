# DLT Operations SOP — Launch Baseline

## 1. Before a Trip
Operations should verify:
- Trip published
- Vehicle assigned
- Seat configuration correct
- Price correct
- Reporting/departure times correct
- Pickup point correct
- Booking window correct
- Boarding staff assigned where applicable

## 2. Before Boarding
- Open trip/boarding workflow
- Confirm manifest
- Confirm scanner
- Confirm vehicle
- Handle last-minute vehicle changes
- Communicate operational changes to affected students

## 3. Boarding
- Scan passenger QR
- Confirm VALID result
- If ALREADY BOARDED, do not board again
- For INVALID, inspect booking/status
- Manual boarding only by authorized Admin
- Record denied boarding with reason

## 4. Departure
- System transitions toward Departed based on schedule.
- Admin can correct actual operational status.

## 5. After Trip
- Confirm completion
- Finalize no-shows
- Review denied boarding
- Review payment/refund exceptions
- Review trip summary
- Student rating becomes available after completion and expected journey window

## 6. Trip Cancellation
- Cancel trip
- System identifies affected bookings
- Automatic full refunds are initiated
- Admin receives affected passenger list
- Use ready-to-send WhatsApp template
- Mark passengers notified
- Reconcile failed/pending refunds

## 7. Major Trip Changes
- Identify affected bookings
- Notify students
- Update trip/pass information
- Apply predefined major-change refund workflow where applicable
- Audit the change
